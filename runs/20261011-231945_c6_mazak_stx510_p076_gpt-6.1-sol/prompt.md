# 電気図面 1 頁の読み取り（label_v7）

あなたは制御盤の電気図面を読む専門家です。図面集「ヤマザキマザック Super Turbo-X 510（レーザ加工機）Electrical Diagram」の PDF 76 頁を読み、指定の JSON Schema に従って結果を返してください。

## このフォルダにあるファイル

- `page.png`：頁全体の画像（300dpi）。この画像と `tile_*.png` の6枚は、この指示と一緒に最初に渡してある。pt に直すと x_pt = x_px × 72 ÷ 300（y も同じ）。頁の大きさは 595 × 842 pt。
- `tiles.json` と `tile_*.png`：頁を分けた拡大画像。各画像が頁のどの範囲（pt）かは `tiles.json` にある。細かい記号は必ずこちらで確かめる。
- `words.json`：頁の文字と位置（pt、頁の左上が原点）。文字の中身と位置はここが正確。
- `graph.json`：頁の線をプログラムで追跡した結果。
  - `points`：要所の点。`kind` は junction_dot（接続の黒丸）、terminal_circle（端子の○）、connector_pin（コネクタの >> または <<）、end（線の端）、bend（線の曲がり角）、symbol_touch（記号の線が始まる所）、branch（黒丸のない分かれ目）。
  - `runs`：点と点の間の線。`a` と `b` は点の ID、`path` は座標の列（pt）。
  - 黒丸のない交差はつながっていない。ダイオードなどを貫いて描かれた線は、記号の所で切ってある。
  - 記号の一部（接点の刃、枠など）も線として入っていることがある。
- `symbols.json` と `symbols/*.png`：記号の候補。プログラムが「線ではない何かが描いてある所」をまとめたもの（意味は決めていない）。候補ごとに、範囲（`bbox`、pt）、そこに触れている点（`points`、P…）、1200dpi の拡大画像（`image`。その画像が頁のどの範囲かは `image_box`）がある。
  - 記号を見分けるときは、必ず候補の拡大画像を見る（全体画像では小さすぎて違いが分からないことがある）。
  - 候補には、記号ではないもの（改訂の印、表題欄の線など）や、隣り合う2つの記号が1つにまとまったものも含まれる。逆に、候補に入っていない記号もあり得る。
- `pages.txt`：図面集の全頁の文字（`=== p.N ===` で頁を区切る）。この頁だけでは分からないこと（線番の決まり、機器の用途、線の行き先、頁番号など）を探すのに使う。

## 使える道具（pdf）

図面を読むための関数を道具として使える。どれも測った事実だけを返す（記号の意味は決めない）。座標は pt、頁の左上が原点。

- `crop`：この頁の好きな範囲を拡大した画像。細かい記号は必ずこれで確かめる。
- `page_image`：図面集の別の頁の画像（部品配置図や表を見るのに使う）。
- `find_text`・`words_in`：文字を、位置・フォント・大きさつきで探す。
- `lines_in`・`line_stats`：線の向き・長さ・太さ、頁の線の太さの分布。
- `trace_from`：graph.json の点から線をたどり、どの点・端子・コネクタに届くかを返す。
- `symbol_features`：記号がありそうな場所（symbols.json の S…）ごとに、線の向き・長さ、斜めの線が縦の線と交わって越えているか、閉じた三角・四角の数、配線の点にどの辺で触れているか。
- `where`：座標が何行目・何列か。
- `search_pages`：図面集の全頁の文字から探す。
- `check`：答えを点検する（正解は使わず、答えの中の食い違いと決まりへの合い方を見る）。
- `preview`：答えから組み立てたネットと回路の筋を見る。
- `run_python`：自分で書いた Python を動かす。このフォルダのファイルは `/work` に（読み取り専用）、この頁の線と文字の全データは `/data/vector.json` にある。標準ライブラリと numpy・Pillow が使える。上の道具で足りない集計や絞り込み、確かめ（例：範囲の中の点を並べる、全頁の文字から複数の言葉をまとめて探す、自分の答えのポートどうしがつながるかを調べる）に使う。結果は print で出す。

使い方の決まり：

1. 端子・要素の両端・PLC 入出力に点を選んだら、`trace_from` でその点からほかの端子や機器に届くことを確かめる。どこにも届かない点は選び直す。
2. 記号を見分けるときは、`crop` で拡大し、`symbol_features` の測った値も見る。
3. 答えを返す前に、必ず `check` を呼ぶ。問題があれば直して、もう一度 `check` を呼ぶ。問題がなくなるまで繰り返す。直せないものは needs_review に理由を書く。
4. 最後に `preview` で回路の筋を見て、おかしな所がないか確かめる。

## 返すもの

1. **頁の情報**：頁名、頁番号（他の頁からの参照に使われる番号。分かれば出所と根拠つき）、書式（向き、位置の表し方、行と列、名前の置き方、接続の描き方）。表題欄（図番・承認・改訂）は要らない。
2. **電源線**：名前、極性（plus・zero・ac・ground・unknown）とその出所、名前が書かれた側の線の端の点。
3. **機器**：図の機器記号を ID にする。括弧の中が機器記号の場合（例「PLC(A2)」）は ID を A2、name を PLC にする。種類、記号の名前、設置場所（どの枠の中か。regions に枠を挙げる）、用途（出所と根拠つき）。
   - **2 端子の要素**（接点、コイル、抵抗、ダイオード、表示灯など）ごとに：種類、接点なら a（普段は開）・b（普段は閉）・c（切り替え）、記号の名前、記号の範囲、**両端の点**。両端の点は、記号のすぐ外で線がつながる点を `graph.json` から選ぶ。1 つの機器が複数の要素を持つことがある（連動する接点など）。その場合も機器は 1 つにして、要素を `elements` に並べる（`SQ4_2` のような、図にない ID を作らない）。
   - 要素の ID は、1 つの機器の中で重ならないようにする。a接点は `a`、b接点は `b`、c接点は `c`、同じ種類が 2 つ以上なら `a1`・`a2`。コイルは `coil`、それ以外は `body`。
   - **端子台・コネクタ・ユニットの端子**：その位置の点（terminal_circle、connector_pin、線の端など）に名前を付ける。
4. **ポート名の決まり**：「機器ID:端子名」。
   - 端子台は `XT1:101`、コネクタは `X5:3` のように、図に書かれた端子番号・ピン番号を使う。
   - 図に端子名がない 2 端子の要素は、接点なら `機器ID:a.1`・`機器ID:a.2`（a・b・c は接点の種類、1 は左または上の端子）、それ以外は `機器ID:1`・`機器ID:2`。端子番号が図に書いてあればそれを使う。
   - 1 つの機器に同じ種類の接点が 2 つ以上あるときは、`機器ID:a1.1`・`機器ID:a2.1` のように番号で分ける（番号は左または上から順）。
   - PLC の入出力は `ユニットID:アドレス`（例 `A2:X1.00`）。
   - 電源線は名前だけを書く（例 `24V+`）。
5. **PLC 入出力**：アドレス（図に書かれたとおり。例 `X1.00`。ユニットの ID は付けない）、入力か出力か、ポート、点、つながる現場の機器、名前（コメント）。
6. **先が描かれていない端**：この頁では線の先が描かれていないポートと、その根拠（`pages.txt` で調べた結果）。
7. **図面集全体の決まり**：頁をまたいで分かった決まり。端子番号を線番とみなせる根拠があれば、id を `terminal_no_is_wire_no` にする。
8. **他頁参照**、**図中の表**（セルは書いてあるとおり）。
9. **未解決と要確認**
   - 読めない所、決められない所は推測で埋めず `unresolved` に書く。
   - 推定で埋めた所、自信のない判断は `needs_review` に書く。人はこのリストだけを確認するので、間違っているかもしれない所は必ず入れる。
   - 出所（basis）は、図に書いてあれば `drawing`、別の頁で分かれば `other_page`（頁番号を根拠に書く）、推定なら `inferred`。`human` は使わない。

座標と点の ID は、`graph.json` と `words.json` にあるものだけを使ってください。
